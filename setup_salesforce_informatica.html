Before You Start

What you need
  • An Informatica IDMC organization with Cloud Data Integration
  • A Salesforce Developer Edition account
  • Permission to configure External Client Apps in Salesforce
  • Postman Desktop (for obtaining the refresh token)
  • Access to an Informatica runtime environment
Training setup that we actually used
  • IDMC organization: J4RVIS
  • Subscription: Data Integration Advanced Trial
  • Informatica connection: Salesforce_Developer
  • Runtime for successful connection test: Informatica Cloud Hosted Agent
  • Salesforce External Client App: Informatica Training
Do not publish secrets: Screenshots and training guides must not contain Consumer Secrets, access tokens, refresh tokens, or authorization codes. Use a secure credential store. Our screenshots in this guide deliberately omit those values.

1. Activate the Salesforce Connector in Informatica

1
Open Informatica IDMC → Data Integration.

On the Data Integration home screen, click Let's get connected!. In our trial UI, that opened Administrator → Connections → New Connection. Alternatively, if Connections is already shown in Administrator's left sidebar, open it directly.

2
Check if Salesforce is in New Connection.

If the Salesforce connector is missing, cancel the wizard and navigate to Administrator → Add-On Connectors. Search for Salesforce.

Actual trial screenshot: Salesforce Connector appears with a Start Free Trial button. Do not confuse it with Salesforce Marketing Cloud or Salesforce Analytics.

3
Activate Salesforce Connector → Start Free Trial.

Follow the activation prompts. Return to Administrator → Connections → New Connection and confirm Salesforce is now offered as a connection type.

Trial activation and connector availability depend on your IDMC organization and licensing. In our J4RVIS trial, the connector appeared after activation.

Actual trial screenshot: Salesforce becomes available in the New Connection wizard.

2. Prepare Salesforce Developer Edition

4
Sign in to your Salesforce Developer Edition organization.

Open Salesforce, select the gear icon, then Setup. You need permissions to manage External Client Apps and an account with API access.

5
Find External Client App Manager.

In Salesforce Setup's Quick Find, search External Client App Manager. Open it and click New External Client App.

We used the modern External Client App rather than creating a legacy Connected App.

3. Configure OAuth in the Salesforce External Client App

7
Under API (Enable OAuth Settings), check Enable OAuth.

The callback URL, OAuth scopes, and security settings appear.

8
Set the Callback URL to Postman's browser callback.
https://oauth.pstmn.io/v1/callback

This is the callback displayed by our Postman Desktop when Authorize using browser was checked. In that mode, Postman greys out the callback field. Use the exact URL shown in your own Postman configuration.

9
Move these two scopes to Selected OAuth Scopes.
Manage user data via APIs (api)
Perform requests at any time (refresh_token, offline_access)

The first scope enables API access. The second permits obtaining a refresh token.

Actual lab screenshot: scopes selected; callback configured; security settings visible.

10
Keep PKCE and the org-required security controls.

Our new External Client App displayed Require PKCE, Refresh Token Rotation, and 30-day idle refresh-token TTL as enabled. Do not attempt to disable organization-mandated controls. The separately named Authorization Code and Credentials Flow checkbox was not needed for the standard web-server authorization code + PKCE flow we used.

11
Create the app and retrieve the Consumer Key and Consumer Secret.

Click Create. From External Client App Manager → Informatica Training → Settings → OAuth Settings, open Consumer Key and Secret. You may need to verify your identity. Store both securely; do not copy them into team training screenshots.

4. Authorize Salesforce in Postman

Why Postman? Informatica's Salesforce OAuth connection form needs an existing refresh token. Postman lets us complete Salesforce's interactive OAuth authorization code + PKCE flow and obtain that token for this training exercise.
12
Open Postman Desktop → New HTTP Request → Authorization.

Select OAuth 2.0. Under Configure New Token, use the values below.

Client AuthenticationSend client credentials in body (as used successfully in our lab)
13
Click Get New Access Token and authorize in Salesforce.

Postman opens the system browser. Sign in to Salesforce Developer Edition, then approve the app if asked. If Firefox blocks the callback's pop-up, allow the pop-up for oauth.pstmn.io and return to Postman.

14
Verify that Postman received both tokens.

In Manage Access Tokens → Token Details, find the Access Token and the field named refresh_token. The refresh_token is the value required by Informatica. Do not mistakenly copy the access token.

Common mistake from our exercise: We initially pasted the wrong token into Informatica. Postman authentication succeeded, but Informatica's Test failed. Using the correct refresh_token resolved it.

Important for the upcoming CSV migration: We successfully tested Salesforce using the Cloud Hosted Agent. A local customers.csv on your Windows laptop is not accessible to that hosted runtime. For CSV → Salesforce from your laptop, use a working local Secure Agent runtime, and configure the relevant source/target connections for that runtime. Don't assume the hosted connection can access local files.

6. Test, Save, and Verify

17
Click Test in Informatica.

Expected result: a green banner stating “The connection test was successful. You can now save the connection.”

Actual screenshot from the completed exercise. Secrets are masked in the form.

18
Click Save and confirm the connection exists.

Open Administrator → Connections and verify Salesforce_Developer is in the list. In the conversation, the Test result was confirmed; the final saved status should be verified separately.

Training completion criteria: connector activated, Salesforce app registered, Postman returns a refresh token, Informatica Test succeeds, and the connection is saved for use in a mapping.

Troubleshooting — Based on Issues We Encountered

Salesforce isn't visible in New Connection

Go to Administrator → Add-On Connectors, search Salesforce, and check whether Salesforce Connector → Start Free Trial is available. This was required in our trial organization. Connector access can vary by subscription.

I don't see Connections in the Administrator sidebar

In our trial, the Data Integration → Let's get connected! shortcut opened the connection workflow, after which Connections was shown in Administrator. Menu availability can also vary by entitlements/permissions; check the actual UI instead of assuming the menu position.

Postman's Callback URL is greyed out

With Authorize using browser enabled, Postman controls this value. Copy the exact callback shown in Postman and set that same value in Salesforce External Client App settings. In our lab it was https://oauth.pstmn.io/v1/callback.

Browser says authenticated, but Postman isn't opening

Allow the oauth.pstmn.io pop-up or application link in your browser, return to Postman, and check Manage Access Tokens. If no token arrived, retry authorization after fixing pop-up handling.

“Failed to get service endpoint URL and access token after retries”

This exact error happened in our training. First confirm that the value pasted into OAuth Refresh Token came from Postman's refresh_token field, not Access Token. Correcting the token made the Test succeed. Other causes are possible; use the detailed error and Salesforce Login History if the token is already correct.

Token works initially, then later fails

Salesforce External Client Apps can enforce refresh-token rotation. A successful one-time connection test does not prove that Informatica reliably persists rotated tokens. For any longer-running integration, test behavior after access-token renewal and confirm support with Informatica.

Hosted Agent works for Salesforce but not my local CSV

This is expected: Cloud Hosted Agent is not your Windows computer. Use a working Secure Agent on the laptop for local files; configure the Salesforce connection for the runtime you will actually use to execute the mapping.
