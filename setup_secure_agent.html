Module 0 · Required Setup

Connect a Windows Computer to Informatica

This guide installs and registers the Informatica Secure Agent, then places it in the training runtime environment. It assumes the student has never installed an Informatica agent before.

Why do we need this? Informatica runs in the cloud, but Exercise 1 uses a CSV file stored on your Windows computer. The Secure Agent is the bridge that lets Informatica execute work against local files and other private resources.

Before Installing Anything

1
Confirm that you have an Informatica IDMC user account.

You must be able to sign in to your organization's Informatica Intelligent Data Management Cloud environment.

2
Confirm that you can open the Administrator service.

After signing in, use the service selector and open Administrator. If you cannot access Administrator or Runtime Environments, check that you are signed in to the correct account and that your account has the required permissions. For an organization-managed account, contact your account administrator if access is restricted.

3
Use a supported 64-bit Windows computer.

Supported operating systems can change. For production use, check the current Informatica Product Availability Matrix. This training uses Windows 64-bit.

4
Make sure no other Secure Agent is already installed on this computer.

If a Secure Agent is already present, do not install a second copy on top of it. Check whether the existing agent is registered to the account you will use for this lab and is running. Reuse it when it meets those requirements. If it serves another environment, use a separate training computer rather than removing an agent that may be in use.

5
Confirm you can run installers as a Windows administrator.

Informatica documents that the Secure Agent must run with appropriate local Administrator permissions on Windows.

6
Confirm internet connectivity.

The Secure Agent uses outbound HTTPS on port 443. If your organization uses a firewall, proxy, VPN, or endpoint security product, make sure it permits the required Informatica domains for your POD.

Corporate networks: if you use an outbound proxy, collect the proxy host, port, and credentials before continuing. If the installer download is blocked, Informatica specifically documents allowing https://global-package.dm.informaticacloud.com.

Part A — Download the Secure Agent

1
Sign in to Informatica IDMC.

Use the same IDMC user that belongs to the organization where you will perform the training.

2
Open Administrator.

Use the Informatica service selector if another service is currently open.

3
Click Runtime Environments in the left navigation.
4
Click Download Runtime Installer.

In some Informatica versions this may be labeled Download Secure Agent. Use the Secure Agent download option, not a serverless or elastic runtime installer.

5
Select Secure Agent as the environment type.
6
Select Windows 64 as the platform.
7
Copy the install token.

Keep it temporarily in a safe place such as Notepad. Informatica states that the install token expires after 24 hours.

8
Click Download.

The Windows installer filename normally resembles:

agent64_install_ng_ext.<agent-core-version>.exe

Part B — Install the Secure Agent on Windows

1
Open your Windows Downloads folder.

Locate the Secure Agent installer you downloaded.

2
Right-click the installer and choose Run as administrator.
3
Approve the Windows User Account Control prompt.

Click Yes when Windows asks whether the installer can make changes to the device.

4
Choose the Secure Agent installation directory.

For a beginner lab, the default installation location is normally appropriate. Informatica advises that the installation path should not contain multibyte characters.

5
Click Next, then Install.

Wait for the files to finish installing. Do not close the installer while it is working.

6
Wait for Informatica Cloud Secure Agent / Secure Agent Manager to open.

After installation, the agent is installed locally but is not yet registered to your Informatica organization.

Part C — Register the Agent with Informatica

1
In Secure Agent Manager, find the registration fields.

You should be prompted for an Informatica User Name and Install Token.

2
Enter your IDMC user name.

This is the user name you use to access Informatica IDMC.

3
Paste the install token you copied earlier.

If the token is older than 24 hours, return to Administrator → Runtime Environments and generate/copy a new install token. You do not need to redownload the installer just because the token expired.

4
Click Register.
5
Wait while the Secure Agent services start.

This can take a few minutes. Do not assume something is wrong immediately after registration.

6
Confirm the local status.

The Secure Agent utility should eventually report:

The Secure Agent and all services are up and running.

Part D — Create the Training Runtime Environment

An installed Secure Agent is the actual software running on the computer. A Secure Agent group / runtime environment is the logical runtime you select when creating Informatica connections and tasks.
1
Return to Administrator → Runtime Environments in your browser.
2
Refresh the Runtime Environments page.

The newly registered Secure Agent may initially appear in an existing group or under unassigned agents, depending on the tenant configuration.

3
Click New Runtime Environment.

This creates the Secure Agent group we will use for training.

4
Name the environment:
LocalTrainingRuntime

You may add a description such as Local Windows runtime for Informatica training, then create/save the runtime environment.

5
Add your Secure Agent to LocalTrainingRuntime.

Open the Actions menu for the new runtime environment and choose Add or Remove Secure Agents. Select your newly registered agent and confirm/save.

Select the Secure Agent registered from your own computer. Its displayed name depends on your installation.

6
Expand LocalTrainingRuntime.

Verify the Secure Agent is now listed underneath the group.

7
Confirm the runtime status is Running.

For the training, the desired end state is:

LocalTrainingRuntime
└── <your Secure Agent>    Running

Part E — Final Verification

1
Leave the Secure Agent service running.

You do not need to keep the small Secure Agent Manager window open. Closing the window does not normally stop the Windows Secure Agent service.

2
Confirm the agent is visible in Informatica after a browser refresh.

If the Runtime Environments page shows the runtime and agent as Running, the cloud tenant can communicate with the agent.

3
Create a local training folder if it does not already exist.

For our lab:

C:\Users\{username}\Documents

Replace {username} with your Windows account folder name. If your Documents folder is in a different location, use its actual path.

4
You are ready for Exercise 1.

The next exercise creates a Flat File connection that uses LocalTrainingRuntime to read customers.csv from this computer.

Troubleshooting

The install token is rejected or expired

Install tokens expire after 24 hours. Return to Administrator → Runtime Environments, use the install-token option to obtain a new token, and register again. You normally do not need to download the installer again.

The Secure Agent installs but remains inactive

Wait several minutes first. If it stays inactive, check internet connectivity, proxy configuration, firewall rules, outbound HTTPS/443, and the correct IDMC POD allowlist. Informatica also recommends checking Windows Event Viewer and Secure Agent logs when startup fails.

The installer download fails

Informatica documents allowing https://global-package.dm.informaticacloud.com through the firewall for Secure Agent installer download failures.

My organization uses a proxy server

Configure the proxy in Secure Agent Manager using the proxy details supplied by your network administrator. Incorrect proxy configuration can prevent registration and keep the agent inactive.

I already have another Secure Agent installed

Do not install a second agent over an existing installation. Decide whether to reuse the existing agent or uninstall it first. Informatica's installation guidance requires that another Secure Agent not already be installed on the machine before a fresh installation.

The Secure Agent is registered but is not in LocalTrainingRuntime

Refresh Runtime Environments. Open the Actions menu for LocalTrainingRuntime and use Add or Remove Secure Agents to select the registered agent. Only agents available to be moved into the group will appear.
